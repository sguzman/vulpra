## Actual custom CA without a global trust override

A dedicated test-only RSA CA and server leaf certificate were generated by OpenSSL in an ephemeral `RUNNER_TEMP` directory. The server leaf included `subjectAltName=IP:127.0.0.1`, `extendedKeyUsage=serverAuth` and the proper private signing key held only in that temporary directory. The TLS fixture served a real HTTPS page strictly on `127.0.0.1`.

The fixture was independently verified in two opposite ways **against the same server**:

1. An ordinary host TLS client with **default trusted roots** rejected its unknown certificate with an actual certificate verification exception.
2. A host TLS client with the **test-only CA explicitly supplied** successfully received and validated the test HTTPS page.

The CA was then added using NSS `certutil` to a brand-new, isolated SQLite NSS `cert9.db` / `key4.db` database under `RUNNER_TEMP`; those database files were zipped as a **Base64-encoded, disposable Firefox profile** and supplied through `moz:firefoxOptions.profile`, a documented native GeckoDriver capability. The temporary original database files' hashes were checked unchanged after browser execution. The separate GeckoDriver-created profile contained only its own copy, and all temporary profiles/CA keys were cleaned when the runner script exited. No OS/system CA store, personal user Firefox profile, machine browser configuration or persistent browser installation was modified.

**At no point was WebDriver `acceptInsecureCerts` enabled**. The browser security decision came from the presence/absence of the explicit test CA in the disposable NSS trust database, not a certificate-error bypass.

## Safe interpretation and remaining acceptance criteria

This **does prove** that the original Firefox160 browser can complete a genuinely certificate-validated HTTPS connection with a temporary explicitly trusted localhost RSA CA, and refuses the same certificate when it is not trusted. In the same source-pinned package, each opt-in missing NSS native provider prevents a usable WebDriver session, *before* TLS/HTTPS navigation. It is compelling evidence those cryptographic providers cannot simply be removed.

This **does not prove** public-site HTTPS behavior, the operating system's general trust chain, TLS 1.3/cipher breadth, mutual TLS, revocation/OCSP, all actual NSS FIPS/PKCS#11/sandbox or Gecko security paths, missing-provider alternative fallback, direct machine-code NSS load callstacks, the complete generated/C++/Rust `dlopen`/`dlsym` dependency graph, all video/hardware backends, the target EndeavourOS/Hyprland mixed-GPU workstation, full security currency, release readiness or permission to prune any original source or native library.
