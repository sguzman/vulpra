## Boundaries

This is more informative than the previous instrumented original-browser `libpulse.so.0` `dlopen` observation ([41492260472](https://github.com/sguzman/vulpra/actions/runs/41492260472)): it observes native glibc symbol bindings with **no symbol-resolution interposition** and confirms provider names in an original browser process actually performing a WebAudio workload. But **`LD_DEBUG` changes timing**, and the observed bindings can include startup/background native activity in that process; they do not establish that the WebAudio click directly triggered each binding or uniquely identify Rust or C source-level callers. The two `/proc/maps` snapshots show residency, not all transient loads/unloads or complete symbol call sequences.

The 197 unique symbol names are **not** a verified complete PulseAudio ABI, and this test does not prove all Rust-to-FFI calls, every original browser feature, a hardware sound path, target EndeavourOS/Hyprland/GPU behavior, source-removal safety, or complete 28-ELF feature/build/runtime/indirect-`dlopen` dependency closure. No browser code or package files were removed, and no new native bytes saved. The sixth M3 gate remains open: **M3 5/6 = 83%; Vulpra 61%; delta +0 percentage points.** The expensive new workflow was restored to **manual-only `workflow_dispatch`** after native acceptance.
